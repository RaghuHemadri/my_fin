# Contributing

Thanks for helping improve this project. It is a research tool, so changes must keep three properties:
- It never places, stages or submits orders.
- It never invents market data.
- It never publishes anyone's personal data.

## Ground rules

- **Never commit secrets or personal data.** API keys go in `~/.config/my_fin/secrets.env`, outside the repo. `portfolio/*.csv`, `reports/`, `memory/`, `state/` and `vendor/` are git-ignored; only the `*.example.csv` files are tracked.
- **Data comes only from configured MCP servers.** Do not add code that calls market-data APIs directly. Local calculators that work on data an agent fetched are fine.
- **Do not hand-edit generated content.** The adapter blocks at the top of upstream skills, the ported agents and prompts, and `docs/skill-coverage.md` are generated by `tools/install_skills.py`. Change the manifest or the installer instead.

## Development setup

- Python 3.11 or later, plus PyYAML for the tests: `python3 -m pip install pyyaml`
- [uv](https://docs.astral.sh/uv/) to run the MCP servers (see the README)

Run the tests before opening a pull request. CI (`.github/workflows/ci.yml`) runs the same suite.

```bash
python3 -B -m unittest discover -s tests -v
```

## Common tasks

### Update the upstream skills

The installed skills are built from Claude Trading Skills and Finance Skills at the commits in `tools/upstream.lock.json`.

```bash
python3 tools/install_skills.py --fetch       # check out the locked commits into vendor/ (git-ignored)
git -C vendor/claude-trading-skills pull      # move to newer upstream commits
git -C vendor/finance-skills pull
python3 tools/install_skills.py               # reinstall and re-adapt every skill
python3 tools/install_skills.py --update-lock # record the new commits
python3 -B -m unittest discover -s tests -v
```

The installer prints `problems`. A new upstream skill is installed as `unreviewed`: add an entry for it to `tools/skills_manifest.json`, then run the installer again. Also review `THIRD_PARTY_NOTICES.md` if an upstream license changed.

### Change what a skill's adapter block says

1. Edit the skill's entry in `tools/skills_manifest.json`. The fields are `status`, `upstream`, `use`, `gaps` and, optionally, `net_scripts`.
2. Run `python3 tools/install_skills.py --refresh`. This regenerates every adapter block, the ported agents' notes and tool lists, and `docs/skill-coverage.md` in place. It does not need `vendor/`.

Write tool names as canonical TradingView MCP names. `.github/tradingview-adapter.md` and `.github/copilot-instructions.md` map them to the configured servers.

### Add your own skill

1. Create `.github/skills/<name>/SKILL.md`. The `name` must equal the folder name: lowercase letters, digits and hyphens, at most 64 characters. The `description` must be at most 1024 characters.
2. Add the name to `OWN_SKILLS` in `tools/install_skills.py`, so the installer never overwrites it and the tests treat it as yours.

### Add or change an agent

Agents live in `.github/agents/<name>.agent.md`, and the `name` must match the file name. Their `tools` may use only built-in tool sets (`read`, `search`, `edit`, `execute` and so on) and the MCP servers configured in `.mcp.json`; a test enforces this.

### Change the data servers

The data servers are configured in several places. Keep them in step:
1. `.mcp.json` and `.vscode/mcp.json` must list the same servers; a test checks this.
2. Update `mcp/launch.sh` and `mcp/register-user-config.sh` if a local server changes.
3. Update the "Financial data sources" section of `.github/copilot-instructions.md`, including its tool and symbol tables.
4. Run `python3 tools/install_skills.py --refresh`, so the adapter blocks and ported agents list the new servers.
5. The TradingAgents role agents (`.github/agents/ta-*.agent.md`) and `investment-debate` name the servers directly. Update them by hand.

## Pull requests

- Keep each change focused, and say what you changed and why.
- Include test results.
- Never include real holdings, reports or keys in examples. Use the sample data in `portfolio/*.example.csv`.
